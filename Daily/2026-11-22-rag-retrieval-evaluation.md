# 2026-11-22 TIL — RAG에서 근거를 먼저 찾는 법

## 오늘 배운 것

RAG는 오픈북 시험과 비슷하다. 질문을 받으면 먼저 관련 자료를 찾고, AI는 그 자료를 읽어 답을 쓴다. 답을 뒷받침하는 출처를 함께 보여주고, 자료가 부족하면 확인할 수 없다고 답한다.

긴 문서를 검색하기 좋은 조각으로 나누는 일을 **청킹**이라고 한다. 이번에는 PDF 한 쪽을 한 조각으로 썼다. **Hit@5**는 정답이 있는 문항에서, 검색 결과 5개 안에 정답 근거를 찾았는지 보는 지표다.

## 직접 해본 것

연습 질문 10개와 정답 기준표를 두고, 같은 질문으로 검색 방법 네 가지를 비교했다. TF-IDF와 BM25는 질문에 나온 단어를 기준으로 자료를 찾는다. 벡터 검색은 뜻이 비슷한 자료를 찾고, 하이브리드 검색은 키워드 검색과 벡터 검색의 순위를 합친다.

이번에는 BM25에 모델 필터를 켰을 때 결과가 가장 좋았다. 모델 필터는 질문에 나온 제품 모델명이 적힌 자료를 먼저 보여준다. 생성 모델과 질문은 그대로 두고, 검색 방식만 바꿔 다시 채점했다.

| 확인한 것 | 기존 TF-IDF | BM25 + 모델 필터 |
|---|---:|---:|
| 검색 상위 5개에서 정답 근거를 찾은 문항 | 6/9 | 9/9 |
| 답변 자동 채점을 통과한 문항 | 6/10 | 10/10 |

답변 채점에는 근거가 없을 때 답변을 보류하는지 확인하는 문항도 포함했다.

## 깨달은 것

처음에는 답변이 틀리면 AI에 주는 지시부터 고쳐야 한다고 생각했다. 이번에는 같은 AI에 더 맞는 근거를 건네는 것만으로 답변 점수가 올랐다. 이제 답이 틀리면 **검색이 정답 근거를 찾았는지**부터 확인하고, 그다음 AI가 근거를 제대로 읽었는지 살펴볼 수 있다.

정답 기준표를 미리 만들어 두니 무엇이 좋아졌는지 비교할 수 있었다. 점수가 오르면서 AI가 읽고 쓴 글의 양을 나타내는 토큰 수도 약 42% 늘었다. 다음에는 새 질문으로도 효과가 이어지는지 확인하고, 필요한 근거만 골라 더 짧게 넘기는 방법을 실험해 보고 싶다.
