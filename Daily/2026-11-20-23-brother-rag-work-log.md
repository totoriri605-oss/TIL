# 2026-11-20~23 TIL — Brother RAG 프로젝트 준비와 답변 검증

Brother 프린터·복합기 설명서를 근거로 질문에 답하고 PDF 출처를 알려주는 RAG를 만들며 배운 내용을 정리했다. 팀원 세 명이 각자 파이프라인을 만들고 같은 질문으로 비교하기로 했고, 내 작업은 `pipelines/sa`에서 진행했다.

## 11월 20일 — 개인 작업 환경 준비

팀 공용 저장소를 로컬에 준비하고 개인 브랜치 `sa/pipeline-dev`를 만들었다. 공용 작업과 내 변경을 구분하기 위해 브랜치와 작업 폴더를 확인했다.

Codex와 Claude Code가 같은 프로젝트 폴더를 읽도록 하고, 프로젝트 목표와 폴더 위치, 팀의 작업 방식, 현재 상태를 공유 메모에 정리했다. 같은 파일을 볼 수 있어도 서로의 대화가 자동으로 공유되는 것은 아니므로 중요한 결정과 진행 상황을 따로 기록해야 했다.

## 11월 21일 — 자료와 작업 범위 확인

공식 PDF는 프로젝트 최상위 `data` 폴더에 두고, 개인 코드는 `pipelines/sa`에서 작업하는 구조를 확인했다. PDF와 인덱스는 Git에 올리지 않고 각자 로컬에서 준비하는 방식이었다.

팀원 각자가 파이프라인을 개발한 다음 비교해 제출할 버전을 고르기로 했으므로, Portal에 연결할 서버 주소와 사전 테스트는 제출 대상을 정할 때 확인할 사항으로 정리했다.

## 11월 22일 — PDF 파싱과 첫 기준 평가

잉크젯과 레이저 공식 설명서 두 개를 준비해 총 1,099쪽의 텍스트를 읽고 페이지 단위 검색 인덱스를 만들었다. PDF에서 텍스트를 꺼내는 과정이 **파싱**, 검색하기 쉽게 목록을 만드는 과정이 **인덱싱**이다.

ADF 사양표를 직접 보며 모델명, 값, 단위, 각주, 문서와 PDF 페이지를 함께 보존하는 청킹을 연습했다. 이어 검색한 상위 5개 결과를 생성 모델에 전달하고, 답변과 출처를 반환하며 근거가 부족하면 보류하도록 연결했다. 초기 API 인증 오류는 키를 교체한 뒤 해결했다.

첫 연습 질문 10개에서는 API가 모두 응답했고 자동 채점은 6/10을 통과했다. 답변 가능한 9문항 중 정답 페이지를 검색 상위 5개에서 찾은 문항은 6개였고, 총 사용량은 23,288토큰이었다. 이후 같은 연습 문항의 검색 비교에서는 BM25와 모델 필터를 함께 썼을 때 Hit@5가 9/9였다. **검색에서 근거를 찾은 비율과 답변의 정답률은 서로 다른 지표**다.

## 11월 23일 — 답변 검토와 청킹 전략

Day 1 질문과 답변, 인용 페이지를 검토하며 비슷한 모델의 용지함 명칭이 혼동되거나 여러 페이지에 걸친 표의 정보가 빠지는 사례를 살펴봤다. DCP-T730DW의 용지함 명칭과 용량, DCP-L2640DW의 인쇄·복사 소비 전력처럼 숫자뿐 아니라 모델과 항목을 함께 확인해야 했다.

이를 바탕으로 자료의 구조에 맞는 청킹을 계획했다.

- 사양표: 모델명, 항목, 값, 단위와 각주를 함께 연결한다.
- 설정 절차: 순서가 있는 단계와 적용 조건, 주의사항을 보존한다.
- 오류 해결: 오류명과 원인, 조치를 연결한다.
- 페이지를 넘어가는 내용: 앞뒤 관계와 실제 PDF 페이지를 유지한다.

작은 청크로 관련 내용을 찾고 필요한 주변 문맥을 함께 전달하는 Small-to-Big 방식도 공부했다. 검색한 조각에 숫자가 있더라도 그 숫자가 어떤 모델과 조건에 적용되는지 함께 확인해야 한다.

## 11월 23일 — 검색과 구조 청킹 실험

새 평가 세트 HOLD20에서 페이지 단위 BM25와 Hybrid는 각각 자동 채점 6/20이었다. 쪽 경계 문항은 두 방식 모두 0/6이었다. 이어 제목·모델·절차를 연결하는 부모–자식 구조 청킹을 실험하자 자동 통과는 12/20, 쪽 경계 문항은 4/6으로 올랐고 보류 문항 3/3은 유지됐다.

이는 해당 문제 세트에서의 **중간 실험 결과**다. 남은 오답은 검색 실패, 필요한 페이지 일부 누락, 근거가 있는데도 잘못 보류한 사례로 나뉘었다. 이미 본 문제만으로 개선하면 과적합할 수 있으므로 새 문항과 원문 검증을 통해 다시 확인할 계획이다.

## 기억할 점

답변이 틀렸을 때는 정답 근거를 검색했는지, 그 근거가 모델에 전달됐는지, 전달된 내용을 답변과 인용에 제대로 반영했는지 차례로 살펴본다. 정답과 페이지 기준도 PDF 원문과 대조해야 하며, 평가용 정답 힌트를 답변 생성 입력에 넣지 않는다.
