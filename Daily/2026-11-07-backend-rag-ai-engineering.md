## 2. 백엔드의 네 가지 역할을 내 말로 설명하기

| 역할 | 내가 이해한 설명 |
|---|---|
| Router | 요청을 받아 담당 서비스로 연결한다. |
| Service | 업무 규칙에 따라 일을 처리한다. |
| Repository | DB에서 데이터를 조회하거나 저장·수정·삭제하는 코드를 둔다. |
| Schema | 어떤 항목을 어떤 자료형으로 주고받을지 정한다. |

처음에는 Router가 접근 허용 여부를 정하는 곳이라고 생각했다. 요청을 받고 연결하는 것이 기본 역할이며, 인증·인가 검사를 연결할 수는 있지만 같은 개념은 아니라는 것을 배웠다.

Repository를 데이터를 보관하는 곳으로 생각하기도 했다. 실제 저장 공간은 DB이고, Repository는 DB에 접근하는 코드라는 차이를 정리했다.

Schema의 데이터 형식 규칙과 Service의 업무 규칙도 구분했다.

### 내가 만든 /health로 연결하기

요청 → Router가 Service로 전달 → Service가 응답 생성 → Schema에 맞춰 반환

```json
{
  "status": "ok",
  "service": "ai-career-backend"
}
```

이 API는 기본 앱 상태 응답이다. DB 연결이나 모든 서비스 기능까지 정상인지 검사하지는 않는다. T13에서는 DB 접근 공간을 마련했고, 실제 연결은 T14 범위였다.

## 4. RAG는 자료를 찾아 참고하며 답하는 방식

RAG는 Retrieval-Augmented Generation의 줄임말이다.

내 말로 설명하면 **AI가 기억만으로 답하지 않고 질문과 관련된 자료를 찾아 참고하며 답하는 방식**이다.

흐름:

1. 사용자의 질문을 받는다.
2. 관련 자료를 검색한다.
3. 질문과 검색한 자료를 모델에 함께 전달한다.
4. 모델이 자료를 참고해 답한다.

자료를 최신으로 유지하고 출처를 보여주는 데 도움이 된다. 다만 검색 자료가 틀리거나 부족하면 답변도 잘못될 수 있다. RAG가 정답이나 개인정보 보호를 자동 보장하지는 않는다.

### 함께 배운 개념

- 청킹: 긴 문서를 검색하기 좋은 작은 단위로 나누기
- 임베딩: 텍스트 등의 특징을 숫자 배열로 표현하기
- 벡터 검색: 숫자 표현의 유사성을 이용해 관련 자료 찾기
- 컨텍스트: 답변을 만들 때 모델에 제공하는 질문·자료 등의 입력
- 환각: 그럴듯하지만 사실과 다른 내용을 생성하는 현상

RAG에는 벡터 검색 외에 키워드 검색 등을 사용할 수도 있다.

## 5. AI 엔지니어 학습 영상 정리

영상을 보고 AI 엔지니어를 기존 모델에 데이터와 도구를 연결해 쓸모 있는 시스템을 만드는 역할로 이해했다. 모델을 만드는 연구자와의 차이를 엔진과 자동차에 비유한 설명이 이해에 도움이 됐다. 실제 직무 범위는 회사마다 다를 수 있다.

학습 내용을 세 단계로 정리했다.

1. 기초: Python, Git, 명령줄, Linux, API
2. AI 기능: 임베딩, 검색, RAG, 에이전트와 도구 사용
3. 배포·운영: 실행 환경 구성, 기록, 모니터링, 비용·보안 관리

AI가 코드를 작성해도 무엇을 왜 만들지, 결과가 맞는지 판단하는 일은 중요하다. 작은 서비스를 만들 때부터 모든 운영 도구를 도입할 필요는 없고 규모에 맞게 선택한다.

### 워크플로와 에이전트

- 워크플로: 보통 미리 정한 순서대로 처리한다.
- 에이전트: 도구 실행 결과를 보고 다음 행동을 선택할 수 있다.

도구 호출과 결과 확인을 반복할 때는 권한·반복 횟수·비용 한도와 중요한 작업의 사용자 확인도 설계해야 한다.

## 6. 만들어보고 싶은 것 — 프로젝트 도우미

우리 반은 GitHub, 개발 가이드, 스프레드시트, 레드마인을 함께 사용한다. 자료가 있어도 어디를 읽고 다음에 무엇을 해야 하는지 이해하기 어려울 수 있다.

레드마인이 일감과 진행 상태를 관리한다면, 프로젝트 도우미는 관련 자료를 찾아 이해하기 쉽게 설명하는 역할로 생각했다.

첫 기능 아이디어:

**일감 번호를 입력하면 작업 목적, 선행조건, 읽어야 할 문서를 근거와 함께 설명하기.**

- 첫 자료: 작업지시서와 개발 가이드
- 답변: 쉽게 설명한 내용과 원문 링크
- 없는 내용: 추측하지 않고 확인 필요 표시
- PR·담당자·진행 상태: 최신 조회나 자료 갱신 필요
- 첫 검증: 반 친구들이 답변을 보고 다음 행동을 알 수 있는지 확인

이는 오늘 정리한 아이디어이며 아직 구현하거나 사용자 검증을 한 것은 아니다.

## 7. 실습 후보 두 가지

### 문서 질문 도우미

공개·직접 작성한 문서 몇 개를 읽고 관련 부분을 검색해 답과 출처를 보여준다. 자료에 없는 질문에 답을 지어내지 않는지도 확인한다.

### CSV 데이터 계산 도우미

가상의 매출 CSV에 대해 미리 만든 Python 계산 도구를 호출하고 결과를 설명한다. 숫자가 직접 계산한 결과와 같은지 확인한다. 처음에는 조회·계산만 허용하고 임의 코드 실행은 제공하지 않는다.

두 실습 모두 학습 계획이며 오늘 완성한 결과물은 아니다.
