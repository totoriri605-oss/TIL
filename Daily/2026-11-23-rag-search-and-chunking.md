# 2026-11-23 TIL — RAG에서 공통 사양표를 놓친 이유

## 오늘 배운 것

제품 모델명이 적힌 페이지를 우선하면 비슷한 제품의 기능을 섞을 가능성을 줄일 수 있다. 그런데 여러 제품에 공통으로 적용되는 사양은 표에 모델명을 반복해서 쓰지 않기도 한다. 검색 점수가 높은 표도 모델명 우선순위를 적용하면 뒤로 밀릴 수 있다.

**Hit@5**는 정답 근거가 있는 질문에서 그 근거가 검색 상위 5개에 들어왔는지 보는 점수다. 실제 답변에서는 숫자와 조건, PDF 인용이 맞는지와 근거가 부족할 때 답변을 보류했는지도 따로 확인했다.

## 직접 해본 것

사양을 묻는 질문이면 설명서의 사양 구역에 검색 가산점을 주는 방법과, 모델이 검색 후보를 다시 읽고 필요한 근거를 고르는 **재순위**를 비교했다. 공개 개발 질문에서는 사양 가산점만으로 검색 적중이 **5/8에서 8/8**로 올랐고, 답변·인용·보류를 함께 채점한 점수는 **7/10에서 10/10**이 됐다. 실험 옵션을 PR로 병합했고 기본 검색 설정은 유지했다.

별도로 만든 질문에서는 사양 가산점을 켜도 검색 적중이 **5/8**로 같았다. 모델명 우선순위만 끄자 **8/8**이 됐다. 놓친 페이지 세 곳에는 질문에 나온 모델명이 직접 등장하지 않았다. 같은 설정으로 이전 질문도 다시 찾아보니, 팀 연습과 공개 개발 질문에서는 각각 한 문항씩 상위 5개에서 빠졌다.

자동 문서 공급장치 사양표 한 곳에서는 모델별 행을 작은 청크로 나누고, 답변에 필요한 각주를 붙였다. 여러 청크를 인용해도 출처는 원래 PDF 페이지로 돌아가도록 확인했다. 이 방식을 적용한 질문 한 개에서는 정답과 인용을 유지하면서 입력이 **3,713토큰에서 2,290토큰으로 38.3%** 줄었다. 절차와 보류 문항을 포함한 전체 비교에서는 두 방식 모두 **8/11**이었다.

## 깨달은 것

정답 페이지가 보이지 않으면 먼저 **어느 단계에서 밀렸는지** 확인하는 게 중요했다. 검색 순위에 영향을 주는 설정을 한 번에 하나씩 바꾸니, 사양 가산점과 모델명 우선순위의 영향을 구분할 수 있었다.

작은 청크를 쓸 때는 표의 값만큼 단위와 각주도 중요했다. 다음에는 모델이 명시된 근거와 공통 사양표를 함께 후보에 남기는 방식을 비교해 보고 싶다. 새 질문을 따로 두고 검색 적중, 답변 정확도, 입력 토큰을 함께 확인할 계획이다.
