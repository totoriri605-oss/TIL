# 팀 프로젝트에서 Git과 AI 도구 함께 쓰기

## 브랜치와 작업 범위

Brother RAG 프로젝트에서는 팀 공용 저장소를 사용하면서 개인 작업을 `sa/pipeline-dev` 브랜치와 `pipelines/sa` 폴더에서 진행했다. 작업 전에는 현재 브랜치와 변경 파일을 확인하고, 팀원의 변경이나 공용 파일을 덮어쓰지 않도록 범위를 구분한다.

커밋 전에는 변경된 파일을 확인하고, 필요한 파일만 선택한다. PDF 원본, 생성된 인덱스, API 키나 `.env`처럼 공유하면 안 되는 자료가 들어가지 않았는지도 확인한다. 팀 공용 브랜치에 반영할 때는 팀의 검토 방식을 따른다.

## Codex와 Claude Code의 작업 맥락

두 도구가 같은 로컬 프로젝트를 열면 같은 파일을 읽을 수 있지만 대화 내용이 자동으로 전달되는 것은 아니다. 프로젝트 목표, 현재 브랜치, 완료한 작업, 다음 작업과 주의사항을 공유 메모에 남기면 이어서 작업하거나 별도로 검토하기 쉽다.

공유 메모는 당시 상태를 기록한 자료다. 이후 파일이나 브랜치가 바뀔 수 있으므로 새 작업을 시작할 때 현재 Git 상태와 실제 파일을 다시 확인한다. AI가 만든 코드와 정답도 실행 결과와 원문을 확인해야 한다.
