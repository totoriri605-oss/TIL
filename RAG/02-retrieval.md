# RAG 검색 방식 비교

## 질문에 맞는 근거를 찾는 방법

- **TF-IDF**: 질문과 문서에 쓰인 단어의 중요도를 바탕으로 비교한다.
- **BM25**: 단어의 출현과 문서 길이 등을 고려하는 키워드 검색이다. 정확한 제품 모델명이나 오류 코드가 중요한 질문에서 유용할 수 있다.
- **벡터 검색**: 질문과 문서의 의미를 숫자 표현으로 바꾸어 비슷한 내용을 찾는다.
- **Hybrid 검색**: 키워드와 벡터 검색을 함께 사용한다. RRF는 각각의 검색 순위를 결합하는 한 방법이다.
- **재순위**: 처음 찾은 후보를 다시 평가해 질문에 더 관련 있는 근거를 위로 올린다. 후보 자체에 정답이 없다면 재순위만으로 찾을 수 없다.

## 직접 비교한 결과

2026년 11월 22일, 동일한 페이지 인덱스와 팀 연습 질문을 이용한 검색 비교에서 정답 페이지가 있는 9문항의 Hit@5는 다음과 같았다. 이 비교에서는 정답 페이지가 둘 이상인 문항도 **하나만 상위 5개에 있어도 적중**으로 계산했다.

| 검색 방식 | Hit@5 |
|---|---:|
| TF-IDF | 6/9 |
| BM25 | 8/9 |
| BM25 + 모델명 우선 | 9/9 |
| 벡터 | 8/9 |
| Hybrid(RRF) | 8/9 |

이 결과는 작은 연습 세트에 한정된다. 정답 페이지 하나를 찾았다고 필요한 모든 근거와 최종 답변이 맞았다는 뜻은 아니다. 실제 답변 정확도는 별도로 평가한다. [11월 22일 실험 기록](../Daily/2026-11-22-rag-retrieval-evaluation.md)

## 모델명 필터에서 배운 점

모델명이 있는 페이지를 우선하면 다른 모델의 내용이 섞이는 것을 줄일 수 있다. 하지만 공통 사양표에는 모델명이 반복되지 않을 수 있어 필요한 페이지가 뒤로 밀릴 위험도 있다. 필터를 켜고 끈 결과를 새 질문과 기존 질문에서 함께 비교해야 한다. [공통 사양표 사례](../Daily/2026-11-23-rag-search-and-chunking.md)
