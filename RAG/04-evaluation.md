# RAG 평가 지표와 오답 분석

## 무엇을 따로 봐야 할까?

| 확인 항목 | 질문 |
|---|---|
| 검색 적중 | 정답 근거가 검색 후보에 들어왔나? |
| 답변 정확도 | 필요한 값과 조건을 모두 답했나? |
| 인용 정확도 | 인용한 문서와 PDF 쪽이 실제 답을 뒷받침하나? |
| 보류 판단 | 근거가 없을 때 보류하고 충분할 때 답했나? |
| 응답 시간·토큰 | 답변에 얼마나 걸렸고 얼마나 사용했나? |

**Hit@5**는 정의한 정답 근거가 검색 상위 5개에 포함됐는지 보는 지표다. 여러 페이지가 필요한 질문에서 하나만 포함되면 적중으로 셀지, 모두 필요한지에 따라 의미가 달라진다. 실험마다 분모와 기준을 함께 적는다.

## 틀렸을 때 따라갈 경로

```text
질문 → 검색 후보 → 실제 전달된 근거 → 생성 답변 → 인용·보류
```

1. 정답 근거가 후보에도 없다면 파싱·청킹·검색을 확인한다.
2. 후보에는 있지만 모델에 전달되지 않았다면 순위와 근거 선택을 확인한다.
3. 근거가 전달됐는데 답이 틀렸거나 보류했다면 모델의 답변과 조건 해석을 살펴본다.
4. 답이 맞더라도 인용이 다른 페이지라면 출처 연결을 확인한다.

## 평가 문제 만들기

정답이 있는 질문과 자료에 정보가 없어 보류해야 할 질문을 함께 준비한다. 각 문항에 정답, 문서 ID, PDF 기준 쪽, 필수 조건을 정리하고 원문과 대조한다. **정답 힌트는 채점에만 사용**하고 생성 모델에 전달하지 않는다.

이미 결과를 보고 개선한 문제는 개발·회귀 확인에 활용하고, 변경을 고정한 후 별도의 새 질문으로 효과가 이어지는지 확인한다. AI가 만든 문제와 정답도 틀릴 수 있으므로 원문 검증이 필요하다. [실제 평가 경험](../Daily/2026-11-20-23-brother-rag-work-log.md)
